## 三、新引入 / 未解决的问题

### 3.1 【P0，高危】标本前缀守卫是"单侧"的，导致短名被吸附到新尿液项目

**现象（生产路径 `idx.Match` 实测）：**

```
输入 白细胞  ->  #222 尿白细胞      ← 血常规项目，落到尿常规
输入 免疫球蛋白IgG -> #77 尿免疫球蛋白IgG
输入 视黄醇结合蛋白 -> #78 尿视黄醇结合蛋白
```

**根因**：`internal/services/testitem_service.go` 的 `containsMatchAllowed` 只从 **input 侧**判定标本前缀：

```go
for _, p := range specimenPrefixes {
    if strings.HasPrefix(input, p) && !strings.HasPrefix(std, p) {  // 只看 input 有没有"尿/粪"
        return false
    }
}
```

当**标准名带前缀、输入不带**时，守卫完全失效。反向包含匹配（`strings.Contains(lowerStd, lowerName)`）于是把"白细胞"命中了"尿白细胞"；又因为反向匹配取"最短标准名"，`尿白细胞`(4 字) 短于 `白细胞计数`(5 字)，稳定胜出。

**这是本次修复自己引入的**：`尿白细胞`(#222)、`尿胆红素`(#219) 等 37 个 `尿*` 项目都是本次新建的，修复前不存在这个吸附目标。

**系统扫描结果**：23 个"前缀剥离后仍命中该标本类项目"的组合。其中需要甄别——

- **必须修**：`白细胞` → `尿白细胞`（血常规高频；库内已有 14 条 `白细胞` 行，未来每导入一份血常规都可能误落）
- **中等风险**：`免疫球蛋白IgG`、`视黄醇结合蛋白`（血清学语义，无血清对应项）
- **可接受**：`比重`/`酸碱度`/`潜血`/`酮体`/`颜色`/`浊度`/`蛋白质`/`亚硝酸盐`/`白细胞酯酶` → 尿常规 OCR 本就常省"尿"字，吸附到尿项目反而是对的；`钙卫蛋白`→粪钙卫蛋白、`便隐血`→粪便隐血 同理

**当前数据未被污染**：库内 `白细胞` 仍正确指向 #20 白细胞计数（14 条）。所以这是**前瞻性风险**（未来导入 + 任何一次 `BackfillTestItemIDs` 才会触发），但它恰好是与本次修复同类、同源的 bug。

### 3.2 【P1】"确定性"未真正实现，且两条匹配路径分叉

修复说明中称反向匹配已"改为确定性选择（最短标准名优先）"、"并列取 id 最小者"。**实现与注释不符**：

```go
revID := int64(0)
revLen := int(^uint(0) >> 1)
for _, c := range candidates {
    if strings.Contains(lowerStd, lowerName) && containsMatchAllowed(name, c.Name) {
        if len(c.Name) < revLen {   // 严格小于：长度并列时保留"先返回者"，没有 id 比较
            revID = c.ID
            revLen = len(c.Name)
        }
    }
}
```

而候选集合来自 `SELECT id, standard_name FROM test_items`，**无 `ORDER BY`**——返回顺序由查询计划决定。实测分叉：

| 输入 | `MatchTestItemByName`（DB 版，走覆盖索引 → 按名称序） | `TestItemIndex.Match`（内存版，全表扫描 → 按 id 序） |
|---|---|---|
| 红细胞 | #33 红细胞压积 ❌ | #31 红细胞计数 ✅ |
| 血小板 | #101 血小板压积 ❌ | #36 血小板计数 ✅ |
| 胆红素 | #219 尿胆红素 ❌ | #6 总胆红素 ✅ |

同一套"相同策略"的注释下，两条路径给出不同答案。长度并列时结果不可预测。

### 3.3 【P2】两份匹配实现，其中一份是死代码

`MatchTestItemByName`（约 95 行）在生产代码中**零调用**——全仓库仅 `TestItemIndex.Match` 被使用（`report.go:355`、`batch_import.go:198`、`BackfillTestItemIDs`）。这 95 行重复实现是 3.1/3.2 不一致的直接来源，也是维护负担。

### 3.4 【P2】`ConfirmReport` 持有写事务期间访问全局连接（既有隐患）

```go
tx, err := database.DB.Begin()          // 占用连接 1
matchRefAndCalcFlagWithTx(tx, id)       // 内部 fetchReportSubjectInfo / LoadTestItemIndex 都在用 DB
LoadItemSignatures(reportID)            // 又用 DB（连接 2）
FindIdenticalReport(...)                // 又用 DB
```

`SetMaxOpenConns(2)`。单请求下可用（连接 2 空闲），但**两个并发 confirm** 会各占一个连接再互等空闲连接，而 `database/sql` 取连接无超时 → 永久阻塞、连接泄漏。

**需要澄清**：这个模式是**本次改动之前就有的**（`matchRefAndCalcFlagWithTx` 内部一直在 tx 持有时查 `DB`），本次只是在同一段里又叠加了 2 次外部查询，扩大了窗口。批量导入路径把去重检查放在 `Begin()` 之前，是安全写法。

### 3.5 【P2】`test_items.standard_name` 缺唯一约束

`MatchTestItemByName` 第 1 级精确匹配用 `QueryRow(...).Scan(&id)`、`idx.Match` 用首个命中即返回——若将来出现重名标准项，两条路径会各自静默取一条。当前无重名，属防御性缺口。

### 3.6 【P3】内容指纹去重的覆盖边界

`ContentSignature` 是 `name|value|unit` 排序后 join 的精确 MD5。因此：

- **漏拦**：同一报告重导但 OCR 输出有细微差异（多一个空格、单位写法不同、多识别一行）→ 指纹不同 → 不拦。这正是重复导入最常见的形态之一。
- **误拦**：同受检者、同采样日期、条目集合完全一致的两份**不同**报告（如两家医院同名同日全套、数值恰好一致）会被硬拦且无覆盖开关。概率极低，但无旁路。
- 设计上的正确取舍：用户在 review 阶段改了任一个值，指纹即变化，实测可正常入库，不会误拦人工修正。

### 3.7 【P3】拦截响应的状态码语义不一致

去重拦截返回 `HTTP 200 + {"code":1,"message":"入库被拦截..."}`，而同一函数其他错误分支返回 `HTTP 500 + code:1`。前端只要判 `code` 就不会出错，但语义不统一；且拦截后报告停留在 `review`，需用户手动删除（提示语已说明，可接受）。

## 四、关联功能影响面与需决策项

### 4.1 受影响调用链（3 处，均走同一套匹配）

| 调用点 | 使用路径 | 是否受 3.1 影响 |
|---|---|---|
| `internal/handlers/report.go:355` 单报告确认/导入 | `idx.Match` | 是 |
| `internal/handlers/batch_import.go:198` 批量导入 | `idx.Match` | 是 |
| `main.go:48` 每次启动的 `BackfillTestItemIDs` | `idx.Match` | 是（仅作用于 NULL 行，当前 0 条可匹配，暂不触发） |

`main.go:48` 是**无条件**执行的回填：目前无害，但只要将来出现一行名含"白细胞"的 NULL 条目，重启即被静默写错。

### 4.2 需用户决策：血糖分析物被拆成两条趋势

| 项目 | 洪峰条数 | 数据示例（重叠日期） |
|---|---|---|
| 葡萄糖 #14（原有） | 15 | 2022-04-26、2023-11-18 |
| 空腹血糖 #65（本次新建） | 19 | 2022-04-26、2023-11-18 |

两者是同一种分析物（血清葡萄糖），现在被拆到两条趋势线，**同一个病人同一个分析物的曲线不完整**。当初建独立项目的理由是"避免空腹/随机血糖混一起"，但代价是趋势被割裂。另外泛称 `血糖` 会被反向匹配吸附到 `空腹血糖`（`葡萄糖` 与 `空腹血糖` 之间无此吸附）。

→ 建议二选一：① 把 `空腹血糖` 作 `葡萄糖` 的别名合并（趋势完整，但丢失空腹/随机区分）；② 保留拆分，同时**移除** `血糖 → 空腹血糖` 的吸附（泛称应落 NULL 或落 `葡萄糖`）。

### 4.3 守卫未覆盖的语义差异（当前库内无此类行，属潜在污染）

| 输入 | 实测结果 | 问题 |
|---|---|---|
| 离子钙 | #13 钙 | 离子钙 1.1~1.3 mmol/L vs 总钙 2.2~2.6，混入即污染纵轴 |
| C反应蛋白 | #40 超敏C反应蛋白 | hs-CRP ≠ CRP |
| 脂蛋白a | #55 载脂蛋白A1 | Lp(a) ≠ ApoA1，单位与量级均不同（正向包含命中："载脂蛋白a1" 含 "脂蛋白a"） |

### 4.4 未改动但相关的既有设计

- `test_items.standard_name` 无唯一约束（3.5）
- `ConfirmReport` 的事务/连接混用（3.4）
- OCR 导入界面的 review 环节是人工兜底：误映射会在复核页显示为"匹配到 X"，理论上可人工纠正——但这不能作为 P0 的免责理由，因为血常规"白细胞"这种高频项一旦错配，用户很难逐份发现
