# 2026-10-02 检验项目「包含匹配」误映射导致趋势图污染

## 现象

趋势页查询洪峰「肌酐」时出现大量非肌酐条目（尿素氮/肌酐、尿肌酐、尿蛋白肌酐比值等），尿肌酐 4496 μmol/L 与血清肌酐 ~100 μmol/L 同轴，趋势图完全失真。

## 根因

`internal/services/testitem_service.go` 第 5 级「包含匹配」无守卫：只要 OCR 名称**包含**标准名（或反之）即自动映射。`尿肌酐`、`尿素氮/肌酐` 等因含"肌酐"二字被挂到肌酐（id=7）下。

全库扫描确认问题系统性存在：血红蛋白←糖化血红蛋白A1c/平均血红蛋白浓度、球蛋白←甲状腺球蛋白抗体/免疫球蛋白、钙←降钙素/肌钙蛋白/草酸钙结晶、钠/钾/氯/镁←尿液项目等。

附带发现：同一 PDF 被换名重复导入（如 hash `9703ef8fc699` 导入 4 次、过敏原筛查 PDF 导入 12 次），同一日期出现多条重复数据点。

## 变更

### 代码

`internal/services/testitem_service.go`：

1. 新增 `cleanDecorations()`：匹配前清洗名称首尾 `*`、`.`、全角/半角空格等装饰字符（修复 `D-二聚体.`、`*尿酸` 这类本可精确命中的情况）。
2. 新增 `containsMatchAllowed(input, std)` 守卫，包含匹配任一侧命中以下规则即拒绝：
   - 输入长度 < 2 字符（如 `磷`、`β` 过于模糊）；
   - 输入含 `/`、`:`、`：` 而标准名不含（比值/复合项目）；
   - 输入含 `比值`/`比例` 而标准名不含 `比`（保留 白球比例→白球比）；
   - 标本前缀不同：`24小时尿`/`尿`/`粪`/`脑脊液`/`胸水`/`腹水`/`精液`；
   - 输入含 `尿` 而标准名不含、或以 `尿+标准名` 开头（尿尿素 vs 尿素、B-型脑尿钠肽 vs 钠）；
   - 否定前缀 `非` 不一致（非高密度脂蛋白胆固醇）；
   - 语义关键词两侧不一致：结晶/沉渣/抗体/糖化/浓度/含量/总量/活性/氧合/高铁/还原/免疫球蛋白/甲状腺/肌钙/降钙/钙卫/微量/前白/同工酶/碱度/脑尿钠肽/肌红/平均/有核。
3. 反向包含匹配（标准名包含输入）改为确定性选择：守卫通过的候选中取**最短标准名**、并列取 id 最小者（修复 `红细胞` 随机命中 `红细胞计数`/`红细胞分布宽度` 的问题）。

> ⚠️ **勘误（2026-10-02 复核发现）**：本条"并列取 id 最小者"**未真正实现**。代码里并列时按 `len(c.Name) < revLen` 比较，长度相等即保留"先返回者"，没有 id 兜底；而候选查询 `SELECT id, standard_name FROM test_items` **无 `ORDER BY`**，顺序由查询计划决定。实测 `MatchTestItemByName` 与 `TestItemIndex.Match` 对 `红细胞`/`血小板`/`胆红素` 返回不同结果。
> 另，同次复核发现标本前缀守卫只检查 input 侧，导致 `白细胞` 被吸附到新建的 `尿白细胞`（P0 回归）。
> 详见 `docs/bugfix/2026-10-02-fix-verification-review.md`（含完整证据链与修复建议）。
4. `MatchTestItemByName` 与 `TestItemIndex.Match` 两处同步生效（调用点：report.go 单报告导入、batch_import.go 批量导入、BackfillTestItemIDs 回填）。

`labtrace.ps1`：修复 `Invoke-Run` 在会话环境变量含大小写重复项（Path/PATH）时 `Start-Process` 抛异常导致无法启动的问题（启动前去重会话环境变量）。

## 后续二：内容级重复导入拦截（2026-10-02 下午）

**根因**：文件 MD5 去重（`file_md5` + 唯一索引 + 4 个上传点检查）早已存在且工作正常，但只能拦截**字节级**重复。本次清理发现的 37 份重复报告，完整 MD5 各不相同（同内容、不同字节的文件，如不同渠道导出的同一张检验单），绕过了文件级去重。

**修复**：新增内容级指纹去重——

1. `internal/services/dedup_service.go`（新文件）：
   - `ItemSignature`（名称+结果+单位）与 `ContentSignature()`：排序后取 MD5，与条目顺序无关、对首尾空白不敏感；
   - `LoadItemSignatures(reportID)` / `FindIdenticalReport(subjectID, sampleDate, excludeID, sig, statuses...)`：同受检者+同采样日期下逐候选比对指纹。
2. `internal/handlers/report.go` `ConfirmReport`：入库确认时与已 `imported` 报告比对指纹，完全一致则回滚并返回提示（HTTP 200 + code=1，前端 alert 直接可读，含冲突报告号）。覆盖单文件 OCR 上传与批量导入两条链路的最终入库关口。
3. `internal/handlers/batch_import.go`：批量导入在写文件/插库前解析条目计算指纹，与 `imported`+`review` 状态报告比对，重复即跳过并记入错误列表（条目提取提前，顺带消除了重复解析）。
4. `internal/services/dedup_service_test.go`（新文件）：指纹顺序无关性/空白容忍/差异敏感性单测。

**验证**：
- 单测通过；`go vet ./...` 全量通过。
- 端到端：克隆已入库报告 #34 为 review 态（#226），confirm → 被拦截（"已有内容完全一致的报告（#34）"，状态保持 review）；改动其中一个数值后 confirm → 正常入库。测试克隆已删除。
- 回归：肌酐趋势 API 25 条全为肌酐（91~130 μmol/L）。
